# Чек-лист проверки Y-Statement ADR

Перед записью ADR проверь все пункты. Если обнаружена ошибка формы, исправь её, не добавляя фактов, которых нет в источнике.

- [ ] Заголовок имеет формат `# ADR-NNNN: {название}` с фактическим номером.
- [ ] Присутствует ровно один раздел `## Y-Statement`.
- [ ] В Y-Statement есть все шесть маркеров в порядке: `В контексте`, `сталкиваясь с`, `мы решили`, `и отвергли`, `чтобы`, `принимая`.
- [ ] Y-Statement состоит ровно из одного предложения.
- [ ] В каждую часть внесены только подтверждённые источником сведения.
- [ ] Отсутствующие сведения обозначены `—`, а не выдуманы.
- [ ] На каждый `—` приходится ровно одна задача в `## Задачи на доработку`.
- [ ] Если `—` отсутствуют, раздел `## Задачи на доработку` отсутствует.
- [ ] `чтобы` выражает цель, а `принимая` — издержку, риск или компромисс; при отсутствии данных ставится `—`.
- [ ] В ADR нет дополнительных разделов Status, Context, Consequences.
- [ ] Номер в заголовке совпадает с номером в имени `adr/adr-NNNN-{slug}.md`.
- [ ] Имя файла содержит латинский `kebab-case` slug, и существующие ADR не перезаписываются.

Прочерки `—` и задачи на доработку допустимы: сами по себе они не считаются ошибкой.
Если какой-либо пункт нельзя проверить в доступной среде, не объявляй его выполненным.
